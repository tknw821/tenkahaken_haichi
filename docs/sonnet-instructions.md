対象ファイル：`index.html`（1ファイル構成。HTML / CSS / JS がすべて入っています）

画面構成・動線（B）は実装済みです。このドキュメントは残りの **A（スマホ操作・共有機能）** と **C（細部の改善）** の指示です。

## 0. 守ること（全フェーズ共通）

- **共有URLの形式を変えない**：`encodeState()` / `decodeState()` の出力・入力形式は変更禁止（既に配布したURLが開けなくなるため）。
- **localStorage のキー（`LS_KEY` / `UI_KEY`）と `S` の構造を変えない**。`ui` への項目追加は可（既存項目の意味は変えない）。
- **B で作った画面構成を崩さない**：ヘッダー（タブ／自動保存表示／戻す・やり直し／ファイルメニュー）、初回案内カード `#onboard`、表示設定パネル `#viewCfg` `#viewCfg2`、次へバー `#nextBar`、出力画面の `#sharePanel` / `#outMain` / `#viewBanner`。
  新しいボタンなどはこれらの中に追加し、ID・クラス名は既存のものを流用すること（`.pri` `.big` `.hint` `.stat` `.toolbar` など）。
- 新しい色やフォントサイズを勝手に増やさない。既存の CSS 変数（`--pri` `--line` `--sub` 等）とクラスを使う。
- 外部ライブラリは追加しない（既存の lz-string / qrcodejs のみ）。
- 既存のコードスタイル（1スペースインデント、短い変数名、`$()` ヘルパー、`mutate()` 経由の状態変更）に合わせる。
- 確認はスマホ幅（iPhone 13 相当 390×664、および 360px 幅）と PC 幅（1300px）の両方で行う。

### B で実装済みの内容（参考）
- ヘッダー：タブ名「① 配置する／② 確認・共有」、自動保存表示 `#saveSt`、「ファイル ▾」メニュー（CSV読込／貼り付け読込／CSV書き出し／全配置クリア／新しい配置図）。スマホでは1段に収まる。

- チーム一覧の欄は初期状態で閉じる。

## フェーズ1：スマホでマップ上をスクロールできない問題（A-1）

### 原因
`svg.map{touch-action:none}` により、マップに触れるとページがスクロールできない。

### 修正内容
1. **出力・閲覧画面**：`#outView svg.map{touch-action:pan-y pinch-zoom}` を追加（出力画面にドラッグ操作はないため）。
2. **編集画面**：
   - `svg.map` の `touch-action` を `pan-y pinch-zoom` に変更。
   - タッチ操作（`pointerType!=='mouse'`）で**メンバーがいるマス**を触ったときは、メンバー一覧の行と同じ「長押ししてからドラッグ」方式にする。
     - `pointerdown` ハンドラ内の、行の長押しタイマー（`d.timer=setTimeout(...,380)`）と同じ仕組みを `d.kind==='cell' && d.mid && d.touch` のときにも適用する。
     - `pointermove` で、長押し成立前に8px以上動いたら `clearTimeout(drag.timer); drag.tapCancel=true;` としてブラウザのスクロールに任せる。
     - 長押しが成立してゴーストを出した後は、既存の `touchmove` の `preventDefault` でスクロールを止める（既存コードのまま）。
     - `pointercancel` が来たら既存どおり `endDrag()`。
   - **マウス操作は従来どおり**（5px動いたら即ドラッグ）。
   - 空きマスのタップ（メンバー選択ダイアログを開く）と、メンバーのいるマスのタップ（選択）は従来どおり動くこと。
3. 長押しでゴーストが出たとき、振動で知らせる（`navigator.vibrate?.(15)`、非対応なら何もしない）。

### 確認項目
- [ ] スマホ幅：編集画面でマップ上を上下にスワイプすると、ページがスクロールする。
- [ ] スマホ幅：出力・閲覧画面で、マップの上からでもスクロールできる。ピンチで拡大できる。
- [ ] スマホ幅：メンバーのいるマスを長押し → ドラッグで移動・入れ替えできる。
- [ ] スマホ幅：マスのタップで選択、空きマスのタップで選択ダイアログ、の既存動作が変わらない。
- [ ] PC：マウスでのドラッグ移動・入れ替え、メンバー表へドロップしての配置解除が従来どおり動く。

## フェーズ2：共有パネルの機能追加（A-4, A-5）

対象：`makeShare()` / `renderQR()` と `#sharePanel`

### 2-1. 共有パネルの中身を作り直す
「共有URL・QRコードを作成」ボタン（`#shareBtn`）を押した後、`#shareBox` に以下を上から順に表示する。

1. URL の文字数表示（既存の警告文はそのまま）
2. URL のテキスト欄（既存 `textarea.urlbox`、読み取り専用）
3. ボタン列（`.toolbar`）：
   - **［URLをコピー］**（`.pri`）：押すたびにコピーする。成功したら1.5秒間ボタンの文字を「コピーしました ✓」に変える。失敗したらテキスト欄を選択状態にしてトーストで手動コピーを促す。コピー処理は関数 `copyText(text)`（成功で true を返す Promise）に切り出し、既存の自動コピーもこれを使う。
   - **［共有…］**：`navigator.share` が使える環境だけ表示。`navigator.share({title:S.title||'三方配置図', url})`。ユーザーがキャンセルしたとき（`AbortError`）は何も表示しない。
4. QR コード（既存 `#qrHost`）
5. QR の下に **［QRコードを画像で保存］** ボタン：
   - qrcodejs が `#qrHost` 内に作る `<canvas>` から PNG を作る。QR の周囲に白い余白（16px 程度）を付けた新しい canvas に描き直してから書き出す（余白がないと読み取りにくいため）。
   - ファイル名：`配置図QR_<タイトル>.png`（タイトルが空なら `配置図QR.png`。ファイル名に使えない文字 `\/:*?"<>|` は `_` に置換）。
   - `navigator.canShare && navigator.canShare({files:[file]})` が真なら `navigator.share({files:[file]})` を使う（iPhone で「画像を保存」やLINEへの送信を選べるようにするため）。そうでなければ `<a download>` でダウンロードする。
   - QR が生成できなかった場合（URLが長すぎる、ライブラリ未読込）はこのボタンを表示しない。

### 2-2. 共有URLが古いまま残らないようにする（A-5）
- 共有URLを作った後でデータを変更した場合、古いURLが表示されたままにならないようにする。
- 方法：`makeShare()` で作成時の `encodeState()` の結果を変数に保持する。`renderOut()` のたびに現在の `encodeState()` と比べ、違っていれば `#shareBox` を隠して `#shareBtn` の文字を「内容が変わりました：共有URLを作り直す」にする。
- 閲覧モード（`viewing`）で開いた場合は、最初から現在のURL（`location.href`）を使って `#shareBox` を表示してよい（閲覧者がそのまま転送・QR保存できるように）。

### 確認項目
- [ ] ［URLをコピー］を何度押してもコピーされ、ボタンの文字が一時的に変わる。
- [ ] ［QRコードを画像で保存］で、白い余白付きの PNG が保存される（PC ではダウンロード）。
- [ ] `navigator.share` がない環境では［共有…］が表示されない。
- [ ] 共有URLを作成 → 編集画面で1人移動 → 共有画面に戻ると、古いURLは表示されず作り直しを促される。
- [ ] 閲覧モードでも共有パネルからコピー・QR保存ができる。
- [ ] 作成されるURLの形式（`#d=1.` で始まる）が変わっていない。以前のURLを開いても正しく表示される。

## フェーズ3：細部の改善（C）

### 3-1. スマホでタップしやすくする（C-1）
`@media(max-width:900px)` 内に以下を追加：
- メンバー行の ✎ ボタン、`.grip`：最小 40×40px。
- `.swatch`：30×30px。
- メンバー行（`.mrow`）の上下余白を少し増やす（高さ 44px 程度になるように）。
- ヘッダーのボタンは変更しない（1段に収めるため B で調整済み）。

### 3-2. メンバー編集欄の色指定を整理する（C-2）
メンバー編集欄（`.edrow`）の「カラー」を以下の構成にする：
- 1行目：色見本（`swatchBar`）＋「チーム色に戻す」ボタン（`m.color` が設定されているときだけ表示。押すと `m.color=''`）。
- 2行目以降は `<details>` の「詳しく指定」の中に入れる：テキスト入力（`data-f="color"`）、カラーピッカー（`data-f="colorpick"`）、色相・彩度・明度スライダー（`hsvBox`）。
- 既存の `data-f` 属性とイベント処理はそのまま流用する。

### 3-3. 閲覧画面を左右切替にする（C-3）
- **スマホ幅（900px 以下）のときだけ**、出力画面の2枚のマップ（`.pair`）を［左陣地］［右陣地］の切替表示にする。
- 切替ボタンは `.seg`（既存の編集画面の `#sideSeg` と同じ見た目）で、`.pair` の直前に置く。
- 選んだ側は `ui.outSide`（`'L'` / `'R'`、初期値 `'L'`）に保存する。
- PC 幅では従来どおり2枚を横に並べ、切替ボタンは非表示。
- 実装は CSS で片方を `display:none` にする方式でよい（`#outView[data-side="R"] .pair>div:first-child{display:none}` など）。

### 3-4. 配置図を画像で保存する（C-4）
- `#outMain` のタイトル行（`.outhead`）の「表示設定」ボタンの左に **［画像で保存］** ボタンを追加。
- 押すと、現在表示中の陣地側のマップ（PC では左陣地）を PNG で保存する。
  - `mapSVG(mirror,{static:true})` の文字列を Blob → Image → canvas（2倍解像度、白背景）の順に描いて PNG にする。
  - 画像の上部にタイトル（`S.title`）を描く。
  - 保存方法はフェーズ2のQR保存と同じ（`navigator.share` → `<a download>` の順）。共通関数 `savePng(canvas, filename)` にまとめる。
  - ファイル名：`配置図_<タイトル>_左陣地.png` など。

### 3-5. 配置操作後の「戻す」ボタン付きトースト（C-5）
- `place()` / `unplace()` の後に「◯◯ を配置しました」「◯◯ と ◯◯ を入れ替えました」「◯◯ を配置から外しました」をトーストで出し、トースト内に［戻す］ボタンを付ける（押すと `undo()`）。
- 今の `#toast` は `pointer-events:none` なので、ボタン付きのときだけ `pointer-events:auto` にする。
- 表示時間は3秒。連続操作では最新の内容に置き換える。

### 3-6. CSV のファイル名にタイトルと日付を入れる（C-7）
- `exportCSV()` のファイル名を `三方配置図_<タイトル>_<YYYYMMDD>.csv` にする（タイトルが空ならタイトル部分を省く。使えない文字は `_` に置換）。

### 3-7. 取り込み確認の文章を具体的にする（C-8）
- 閲覧モードの［このデータを編集に取り込む］の確認画面で、ブラウザ保存中の編集データの人数を表示する。
  - `localStorage.getItem(LS_KEY)` を `sanitize(JSON.parse(...))` して `members.length` を数える。
  - 例：「あなたの編集データ（メンバー12名・配置10名）は、この共有データで上書きされます。必要なら先に編集画面の［ファイル］→［CSVで書き出し］で保存してください。」
  - 編集データが空なら「上書き」の警告は出さず、通常の確認文にする。

### 確認項目
- [ ] スマホ幅で ✎・≡・色見本が押しやすい大きさになっている。
- [ ] メンバー編集欄が短くなり、「詳しく指定」を開けば従来どおり色を細かく指定できる。
- [ ] スマホ幅の出力・閲覧画面で左右を切り替えられ、選んだ側がリロード後も保持される。PC幅では2枚並び。
- [ ] ［画像で保存］でタイトル入りの PNG が保存される。
- [ ] 配置・入れ替え・配置解除のあと、トーストの［戻す］で元に戻る。
- [ ] CSV のファイル名にタイトルと日付が入る。
- [ ] 取り込み確認画面に既存データの人数が表示される。
- [ ] フェーズ1・2の確認項目が引き続きすべて満たされている。
